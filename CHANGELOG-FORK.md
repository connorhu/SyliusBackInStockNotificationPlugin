# Fork changelog

This file tracks the rounds of the pre-order work done in this fork of
`webgriffe/SyliusBackInStockNotificationPlugin` (see `docs/preorder-design.md`). One line per round.

- Round 1: PostgreSQL-safe migrations (platform branch in both existing migrations), PostgreSQL 17 CI job, unit-test suite (`phpunit.unit.xml.dist`), design document, test application excludes the Messenger table from the schema check (`schema_filter`).
- Round 2: subscriptions get a `product` relation, a configurable `product`/`variant` target (`TargetResolver`), a lifecycle `status` (waiting/notified/fulfilled/cancelled, replaces `notify`), canonical e-mail and name, hold/dismiss fields; migration `Version20261030100000` (PostgreSQL + MySQL), UPGRADE-6.0.md.
- Round 3: pre-orderability: `Preorderability` enum, `PreorderabilityResolver` (product, taxon ancestry, channel default), host-entity traits/interfaces for product, taxon and channel settings, admin form fields via twig hooks, product-page block gated; migration `Version20261030110000` (PostgreSQL + MySQL); the test application maps Product, Taxon and Channel with the new traits so the schema check stays in sync.
- Round 4: guest pre-order with a name field, account linking (a guest e-mail of a customer with a shop user attaches the pre-order to that customer), confirmation mail with the manage link or the account link, and the signed 24-hour manage page (delete, delete all, 10-minute undo, rate-limited new-link request); upstream's GET delete-by-hash route is removed; adds `symfony/rate-limiter`.
- Round 5: pre-order rate limit (one new pre-order per e-mail/customer per channel interval, checked in the database; sliding window of 10 per hour per client IP via the `webgriffe_bisn_preorder_ip` limiter; a duplicate never consumes a token) with a friendly, interval-aware message that keeps the form data, and a honeypot that answers a bot with the guest success state without storing or mailing.
- Round 6: restock processing rewrites the `alert` command around `RestockProcessor` (expire lapsed holds with a `hold_expired` mail, move notified pre-orders of a sold-out target back to waiting, allocate free units = sellable units minus active holds: `fastest` notifies everyone, `queue` holds one unit per pre-order for the channel's hold hours, in `createdAt` order), `SellableUnits` (Sylius' plain availability, enabled, in channel, priced), state flushed per target before its mails, `LockableTrait` against overlapping runs (adds `symfony/lock`), cron every 5 minutes.
- Round 7: hold enforcement (`HoldAwareAvailabilityChecker` decorates `sylius.checker.inventory.availability` for shop-section requests only: units held for other pre-orders are subtracted for a visitor who may not buy them), `HoldVisitor` (logged-in customer by customer or canonical e-mail, plus claimed pre-orders), signed claim links in the `alert` mail (`ClaimLinkGenerator`, route `webgriffe_back_in_stock_notification_claim`, valid until the hold ends, session-only `ClaimSession`), fulfilment on `sylius.order.post_complete` (`OrderCompletedListener`, never breaks the checkout), `PreorderStateResolver` / `PreorderView` / `PreorderState` for templates, repository `findActiveByVisitor()`, `queuePosition()`, `activeHoldDeadlinesByProduct()`, `accountSummary()`.
- Round 8: neutral UI for every pre-order state (product-page block with cancel/undo, `AccountController` page with per-state rows, cancel/undo/dismiss, batched queue positions), admin grid with status badges, hold deadline, filters and cancel action, `PreorderExtension` Twig helpers (`webgriffe_bisn_view`, `webgriffe_bisn_account_summary`, `webgriffe_bisn_hold_deadlines`), `display_timezone` option, complete `en` and `hu` translations, README fork section.
- Final review fixes (on round 8): holds whose unit is gone are released without a `hold_expired` mail and never shown as held, claimed pre-orders are fulfilled whatever the checkout e-mail, undo refuses to create a second active pre-order of one person for one target (`SubscriptionRestorer`), a guest duplicate is remembered in the session like a created one, the `alert` lock is per installation and environment, hold deadlines use `display_timezone` in the mail and the admin grid.
- Sylius 2.3: `sylius/twig-hooks` allows `^0.10` – `^0.14` (Sylius 2.3 requires `^0.12 || ^0.14`), CI gets a Sylius `^2.3` / PHP 8.3 / Symfony `^7.3` job.
- Symfony 8: every `symfony/*` constraint also allows `^8.0`, `doctrine/dbal` `^4.0` and `doctrine/persistence` `^4.0` (Symfony 8.1 needs DBAL ≥ 4.3); the lifecycle migration writes the `(DC2Type:…)` comments only on DBAL 3; CI gets a Sylius `^2.3` / PHP 8.4 / Symfony `^8.0` job.
